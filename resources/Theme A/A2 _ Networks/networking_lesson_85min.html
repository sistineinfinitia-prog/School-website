Online Banking

Checking your balance and transferring funds

✅ Client-Server. Banks need centralised control and security. Your login goes to their server which verifies credentials and manages your account data securely.

BitTorrent Download

Downloading a large file using torrent software

✅ Peer-to-Peer. Pieces of the file are downloaded simultaneously from many different users (seeders), distributing the load and often making downloads faster.

Email (Gmail/Outlook)

Sending and receiving emails

✅ Client-Server. Your email client connects to a mail server. The server stores emails and routes them to recipients' mail servers — a central hub model.
📞

Skype / Zoom Call

Making a video call to someone

✅ Hybrid! Server sets up and manages the call (client-server), but the actual audio/video may flow directly peer-to-peer to reduce latency and improve quality.
🌐

Browsing www.bbc.co.uk

Loading a news website in your browser

✅ Client-Server. Your browser (client) sends an HTTP request to BBC's web servers. The server responds with the webpage content displayed in your browser.
₿

Bitcoin Transaction

Sending cryptocurrency to someone

✅ Peer-to-Peer. Transactions broadcast to the P2P network of nodes. Each node holds a copy of the blockchain. No central authority validates transactions — the network does.

🗺️ Activity C — Concept Explorer

Click each concept to expand and explore. Can you explain each one in your own words after reading?

Network Segmentation ▾

The overall strategy of dividing a large network into smaller, more manageable zones — like departments in a company. Achieved using routers, switches, firewalls, and special protocols.

Key benefit: If one segment is breached, attackers can't easily move to others. Think of watertight compartments on a ship!

Subnetting ▾

Divides a network into smaller subnetworks based on IP addresses. Like assigning different area codes to different cities.

Key benefit: Routers make smarter routing decisions — data only travels to relevant subnets, reducing broadcast traffic and congestion.

VLANs (Virtual LANs) ▾

Groups devices by function or department regardless of physical location. The HR VLAN and Finance VLAN can share the same physical switches but remain logically separated.

Key benefit: Creates separate broadcast domains — traffic in one VLAN stays in that VLAN. You can also apply different security rules per VLAN.

Access Control ▾

Segmentation allows network admins to restrict who can access what. Only authorised users/devices in a specific segment can reach sensitive resources.

Key benefit: Reduces the "blast radius" of a cyberattack. Even if attackers get in, they're limited to one segment.

🔥 Challenge 1 — Analyse the Breach

📖 Scenario: A multinational company runs all its departments (Finance, HR, R&D, Customer Service) on a single, flat network with no segmentation. A phishing email tricks an HR employee, and attackers gain access to the network. Within hours, they have accessed R&D source code and customer payment data.

Foundation

List 2 problems that a flat (non-segmented) network caused in this breach.

Core

Explain how implementing VLANs could have limited the impact of this attack. Use technical vocabulary.

Extension

Evaluate the most effective segmentation strategy for this company. Consider: cost, security level, manageability, and what model (subnetting vs VLANs vs both) you'd recommend and why.

Foundation: 1) Attackers could move freely between departments once inside. 2) There was no access control stopping HR-level access from reaching Finance/R&D data.

Core: VLANs would have isolated HR, Finance, R&D, and Customer Service into separate broadcast domains. Even with access to the HR VLAN, the attacker could not cross to R&D or Finance without router-level authorisation between VLANs (inter-VLAN routing controlled by ACLs/firewalls).

Extension: Best strategy = VLANs + subnetting + firewalls. VLANs provide logical isolation per department. Subnetting allows IP-based routing controls. Firewalls between VLANs enforce strict access policies. Cost is moderate (switch configuration + firewall rules). This is more manageable than physical separation and provides layered defence-in-depth.

🔥 Challenge 2 — Design a Network

A school wants to design a network for: Students, Teachers, Admin/Finance, and Guest WiFi. They have one physical building with multiple floors.

Design the network segmentation strategy. Consider:

  • Which groups should be isolated from each other and why?
  • Would you use VLANs, subnetting, or both?
  • What security boundaries are most important?
  • What model (client-server/P2P) would underpin the overall network?
Recommended Design:
  • 4 VLANs: Student (VLAN 10), Teacher (VLAN 20), Admin/Finance (VLAN 30), Guest (VLAN 40)
  • Admin/Finance most isolated — firewall rules prevent student/teacher access. Contains sensitive payroll and personal data.
  • Guest VLAN internet access only — no internal resources reachable. DMZ configuration.
  • Subnetting assigns different IP ranges per VLAN for clean routing.
  • Client-server model for central authentication (Active Directory server) — teachers and students log in with credentials managed centrally.
  • Firewalls between each VLAN for inter-VLAN traffic control.

🔥🔥 Challenge 3 — Critical Evaluation

EXTENSION

"Network segmentation always improves security." Evaluate this statement. To what extent do you agree? Use examples and consider counter-arguments.

Think about: What could segmentation not protect against? Are there any risks introduced by segmentation? What happens if it's misconfigured?
Model Points (AO2/AO3 level):
✅ Agree: Contains breaches to single segments, reduces attack surface, enforces least-privilege access, makes monitoring easier.
❌ Counter: Insider threats operating within an authorised segment bypass segmentation. Misconfigured VLAN rules can create unintended access paths. Over-segmentation increases complexity → human error risk. Doesn't protect against encrypted C2 traffic that passes through firewall rules.
⚖️ Conclusion: Segmentation is a highly effective layer of security but not a complete solution — must be combined with monitoring, authentication, encryption, and user training.

🗺️ Big Picture — Linking the Concepts

Click the buttons to reveal how today's concepts connect to each other and to the real world.

Models → Security

Client-server models centralise security control (easier to enforce policies) but create high-value targets. P2P distributes risk but makes it harder to enforce security consistently. Segmentation is your tool for limiting impact when any model is compromised.

Segmentation → Performance

Broadcast traffic is the main performance killer in large networks. VLANs contain broadcasts within segments. Subnetting directs traffic only to relevant devices. Together, they reduce noise and optimise bandwidth for high-priority applications.

Real World Applications

🏥 Hospitals: Client-server for patient records + VLANs separating clinical/admin/IoT devices | 🏫 Schools: VLANs per user group | 🏦 Banks: Heavily segmented networks with DMZs for online banking | ☁️ Cloud providers: Micro-segmentation for tenant isolation

Exam Tips

  • "Compare" = give both similarities AND differences with analysis
  • "Evaluate" = weigh up pros and cons, reach a justified conclusion
  • Always use technical vocabulary: broadcast domain, VLAN, subnet mask, CIDR
  • Link to real examples to gain application marks
  • For security questions: think Confidentiality, Integrity, Availability (CIA triad)
